[지문/요구사항]:
[실무형 1] Linux 환경의 패킷 필터링 도구인 IPTables 방화벽 규칙과 관련하여 다음 물음에 답하시오.

1) IPTables의 기본 3대 빌트인 Chain인 INPUT, FORWARD, OUTPUT 체인의 역할을 각각 설명하시오. (6점)
2) 다음 등록된 IPTables 보안 룰의 동작 의미를 구체적으로 분석하여 설명하시오. (10점)

[IPTables 설정 규칙]
iptables -A INPUT -p tcp ! --syn -m state --state NEW -j LOG --log-prefix "[Faked NEW request]"
--------------------------------------------------------------------------------
[모범 답안]:
1) INPUT: 방화벽 호스트 자신으로 들어오는 인바운드 패킷 검사 / FORWARD: 호스트를 통과하여 다른 곳으로 포워딩되는 패킷 검사 / OUTPUT: 방화벽 호스트에서 생성되어 나가는 아웃바운드 패킷 검사
2) TCP 프로토콜 패킷 중 연결 상태가 NEW(신규 세션 수립)인데도 TCP SYN 플래그가 켜져 있지 않은 비정상적인 스캔/공격 패킷을 탐지하여, 커널 로그에 '[Faked NEW request]' 접두어를 붙여 시스템 로그에 남기도록 하는 룰입니다.
--------------------------------------------------------------------------------
[소문항 (2개)]:
  - 소문항 1 (6점): INPUT, FORWARD, OUTPUT 체인 역할 설명
    키워드: None
  - 소문항 2 (10점): 설정된 방화벽 룰의 상세 분석
    키워드: None
--------------------------------------------------------------------------------
[해설 - Overview]: 정상적인 TCP 3-way Handshake의 첫 패킷은 반드시 SYN 플래그가 설정되어 있어야 합니다. 상태 추적(state) 모듈에서 NEW 상태인데 SYN이 아닌 패킷은 위조된 비정상 패킷입니다.

[22/24] Q-PRAC-022 | Concept: CON-SYS-03 | Category: 시스템 보안 | Score: 16점

[지문/요구사항]:
다음은 리눅스 서버에서 아파치 웹 서버의 접근 로그(`/var/log/httpd/access_log`)를 관리하기 위해 작성된 logrotate 설정 파일(`/etc/logrotate.d/httpd`)의 내용이다. 설정을 분석하고 각 질문에 답하시오.

[logrotate 설정 파일 내용]

    weekly
    rotate 4
    create 0640 root adm
    compress
    missingok
    notifempty
    sharedscripts
    postrotate
        /bin/systemctl reload httpd.service > /dev/null 2>/dev/null || true
    endscript
}

1) 위 설정 파일에서 지정된 `weekly`, `rotate 4`, `create 0640 root adm`, `compress` 지시자의 기술적 역할을 각각 서술하시오. (8점)
2) 관리자가 `compress` 옵션을 적용했을 때 생성되는 순환 로그 파일의 확장자 형태와, 만약 `postrotate` 스크립트를 정의하지 않았을 경우 웹 데몬(`httpd`)에서 발생할 수 있는 로그 기록 장애 현상을 서술하시오. (4점)

--------------------------------------------------------------------------------
[모범 답안]:
1) 지시자 기술적 역할:
- weekly: 로그 파일을 1주일(주 단위) 주기로 순환(Rotate)한다.
- rotate 4: 순환된 백업 로그 파일을 최대 4개까지 보관하며, 4개를 초과하는 가장 오래된 로그 파일은 자동 삭제한다.
- create 0640 root adm: 기존 로그 파일 순환(이동) 직후 새로운 빈 로그 파일을 생성할 때, 퍼미션을 0640(소유자 rw-, 그룹 r--, 기타 ---), 소유자를 root, 소유 그룹을 adm으로 지정하여 생성한다.
- compress: 순환되어 보관되는 이전 로그 파일들을 디스크 절약을 위해 gzip 형식(.gz)으로 압축하여 저장한다.
2) 확장자 및 장애 원인:
- 확장자 형태: `access_log-YYYYMMDD.gz` 또는 `access_log.1.gz` 형태의 gzip 압축 파일
- 로그 기록 장애 현상: 리눅스는 파일명 기반이 아닌 파일 디스크립터(Inode)를 기준으로 파일을 기록하므로, 기존 로그 파일이 다른 이름으로 이동(Rename)된 후에도 아파치 프로세스가 여전히 이동된 이전 로그 파일의 파일 디스크립터를 물고 있어, 새로운 로그 파일이 생성되었음에도 새로운 파일에 로그가 기록되지 않고 순환된 과거 파일에 로그가 계속 기록되거나 로그 유실이 발생한다. 이를 방지하기 위해 postrotate에서 데몬을 리로드(reload)하여 파일 디스크립터를 새로 갱신해 주어야 한다.
3) 점검 명령어 옵션:
- 사전 테스트(Dry-run) 옵션: `logrotate -d /etc/logrotate.d/httpd` (또는 `--debug`)
- 강제 즉시 실행 옵션: `logrotate -f /etc/logrotate.d/httpd` (또는 `--force`)
--------------------------------------------------------------------------------

    키워드: None

    키워드: None

    키워드: None

[해설 - Overview]: logrotate는 weekly, rotate, create, compress 옵션으로 로그를 순환하고, postrotate를 통해 데몬을 reload하여 파일 디스크립터를 갱신하며, -d(테스트), -f(강제) 옵션을 제공합니다 (SRC-06 p.207, 12회 기출).

1) 스머프 공격 메커니즘: 공격자가 패킷의 출발지 IP(Source IP)를 공격 대상(피해자)의 IP 주소로 위조(IP Spoofing)한 후, 목적지 IP(Destination IP)를 특정 네트워크의 브로드캐스트 주소(예: 192.168.1.255)로 설정한 ICMP Echo Request(Ping) 패킷을 다량 전송한다. 해당 서브넷의 모든 활성 호스트들이 일제히 위조된 출발지 IP(피해자 서버)로 대량의 ICMP Echo Reply 응답을 일시에 반사 전송함으로써 피해자의 네트워크 대역폭과 시스템 자원을 고갈시킨다.
2) ( ① ), ( ② ) 명령어:
- ( ① ): `access-list 100 deny icmp 192.168.1.0 0.0.0.255 any` (또는 `deny ip 192.168.1.0 0.0.0.255 any`)
- ( ② ): `interface FastEthernet0/0` (또는 `int fa0/0`)
3) ( ③ ) 명령어 및 원리:
- 명령어: `no ip directed-broadcast`
- 원리: 외부에서 라우터로 유입된 특정 서브넷 대상의 유니캐스트 패킷이 해당 인터페이스의 로컬 브로드캐스트로 전환되는 것을 차단함으로써, 브로드캐스트 대역으로 전송된 패킷이 서브넷 내부의 수많은 호스트들에게 일제히 증폭 전달되는 현상을 원천 방지한다.
